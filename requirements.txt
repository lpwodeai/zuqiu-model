# ============================================================
# CI 流程落地（C-20260928-035 治本方案 ③）
# ------------------------------------------------------------
# .github/workflows/python-tests.yml 三 job 结构：
#   test  (matrix 6: ubuntu/windows × 3.11/3.12/3.14)
#         pip install pip-tools
#         pip-compile --no-emit-options -o requirements.lock requirements.txt
#         pip install -r requirements.lock      # 装精确版本
#         pytest tests -v
#   lint  (1: ubuntu-latest × 3.12, continue-on-error=true)
#         flake8 + pylint                       # 仅报告，不阻断
#   audit (1: ubuntu-latest × 3.12, 默认阻断)   # C-035 新增
#         pip install pip-audit
#         pip-audit -r requirements.txt         # 扫描 CVE（PyPI Advisory + OSV.dev）
#                                                # 发现已知漏洞退出码非零，阻断 CI
#
# CVE 豁免流程：
#   1) 在 workflow 的 audit job 的 pip-audit 命令追加 `--ignore-vuln <CVE-ID>`
#   2) 在本文件头注释登记豁免原因 + 期限 + 跟踪 issue
#   3) 上游修复后立即移除豁免并升级到修复版本
#
# 锁文件不入仓：
#   .gitignore 已加 `requirements.lock` 规则，CI 每次 push 重新
#   生成，永不入 git 索引——避免 lock 与 requirements.txt 双源
#   不同步。
