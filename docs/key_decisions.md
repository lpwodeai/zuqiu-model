### D-20260817-040：走水概率校准方案 — 拒绝 LoRA，采用概率下限

**决策日期**: 2026-08-17
**决策类型**: 模型
**决策状态**: ✅ 已完成
**决策者**: 模型优化团队

**背景**:
西甲第1轮回测发现 T-005 v3 走水概率系统性低估 (2.5%~4.9% vs 实际 25%)。用户提议将走水判定区间从 2.5% 扩大至 15%，并询问是否需要 LoRA 微调。

**决策内容**:
1. **拒绝 LoRA**: T-005 v3 是 LightGBM 树模型，LoRA (Low-Rank Adaptation) 是为大语言模型/Transformer 设计的参数高效微调技术，完全不适用于树模型

3. 走水概率 15% 跨度太大（会使 4/4 场都预测走水），8% 是更合理的中间值
4. 备选方案：如需更精确校准，可重新训练走水检测器（调整 class_weight）或使用 Platt Scaling 校准

**执行结果**:
- 新增 `T005V3_DRAW_PROB_FLOOR = 0.08` 配置
- 温度缩放后自动应用下限 + 重归一化
- 日志记录走水概率变化（before→after）

### D-20260829-051：未赛赔率快照 + 回踩 APPEND 机制

**决策日期**: 2026-08-29
**决策类型**: 数据
**决策状态**: ⏳ 待实施
**决策者**: 模型优化团队

**背景**:
采集 26/27 五大联赛数据时发现，500.com 采集器（final_500_collector.py）对**未开赛**比赛的投注分析（touzhi）和百家欧指（ouzhi）也是全量采集的，但 `write_betting` / `write_ouzhi` 使用 `INSERT OR REPLACE`（主键 fid）覆盖式写入，`is_already_collected` 看到 betting+ouzhi 已存在即跳过（`--skip-existing` 默认开启）。而赔率是随时间变动的时序数据（`init_*` 初盘固定，`live_*` 即时会变，投注倾向随投注量实时波动），当前库只能留「最后一次抓取」的一帧，无法支撑「时序赔率多快照」回测需求。

**决策内容（待实施）**:
1. 新增赔率快照表（主键 `fid + snapshot_time` 联合），每次回踩 `INSERT` 新行而非 `REPLACE`，保留多时刻赔率帧
2. 回踩刷新必须用 `--no-skip-existing` 关闭默认跳过（当前默认 skip 会导致未赛赔率永远不刷新）
3. 明确口径：初盘 `avg_init_*` 固定一次抓够；即时 `avg_live_*` / 投注倾向需临场前回踩取「收盘/临场」帧

**预期用途**: 历史回测对齐「临场收盘赔率」，及后续「时序赔率 22 维」多快照特征接入

**关联文件**: collection/final_500_collector.py（write_betting / write_ouzhi / is_already_collected）
