## 一、问题定义

同一物理场次在竞彩时序表里存在**两个日期键**（销售日跨零点分裂）：

| 键 | WDL | 让球 | 总进球 | 比分 |
|---|---|---|---|---|
| `2026-10-19_Tottenham Hotspur_Coventry City` | 5 | 4 | 4 | 56 |
| `2026-10-20_Tottenham Hotspur_Coventry City` | 1 | 1 | 1 | 28 |

- 赛前报告读 10-19 键（完整 5 个快照）；
- 复盘数据质量读 10-20 键（仅 1 条开盘）→ 扣分 0.1 → "竞彩快照仅 1 条（<2），缺开盘→即时漂移"。
- 同一场比赛，两个下游给出相反结论。
- 追加实测：复盘侧 `get_odds_timeline` 返回 `drift_max=0.0`（开盘=末条）→ **"赔率异动"归因维度对这些场次系统性失明**，不只是数据质量扣分。

### 三段根因

| 环节 | 行为 | 位置 |
|---|---|---|
| 写入 | 采集按"销售日/采集日"自造键，同一场可分裂两键 | `sporttery_live_collector.py`（match_id 由日期+队名拼） |
| 赛前读取 | ±3 天窗口内取"四表记录总数最多"的单键（C-20261016-117 已修） | `generate_unified_report.find_sporttery_match_id` |
| 复盘读取 | 比赛日精确键优先，命中即返回，不查邻日键 | `attribution_engine._find_odds_match_id` |

## 二、预检结果（2026-10-22，只读）

### 预检 A：90 对键"赛前现值 vs 合并值"对拍

| 指标 | 结果 |
|---|---|
| 26/27 竞彩键数 | 390 |
| ±1 天同对阵键对 | 90 |
| 合并后与"最富单键"**完全等价**（逐表去重后） | **90 / 90** |
| 合并后会新增记录（红线） | **0** |
| 一侧为空键（从无到有） | 0 |
| 主客反转（双赛碰撞疑点） | 0 |

本场逐表独有行：10-20 键独有行 **0**；10-19 键独有行 4/3/3/28（WDL/让球/总进球/比分）。
→ **读取侧 ±1 天合并 = 赛前解析器现值，不改变任何预测输入**。

### 预检 B：`matches.actual_wdl` 回填对 Elo 的影响

按 `elo_engine.compute_elo_ratings` 同款口径（初始 1500 / K=30 / 主场 +100）双轨重放：

| 指标 | 结果 |
|---|---|
| 回填场次 | 5（4 场 `actual_wdl=NULL` + 1 场空串） |
| Elo 快照变动 | **24 条** |
| 受影响球队 | **12 支**（含别名分裂：`Coventry City` / `考文垂` 各算一队） |
| 最大变动 | 曼城 2026-09-05：无快照 → 1751.85 |

→ **`actual_wdl` 回填会改变 Elo 序列 = 改变特征 = 改变预测**，冻结期禁止；且窗口 C 执行时必须与 fresh 池批次隔离。
→ `actual_score` 回填**不参与 Elo**（Elo 仅读 `actual_wdl`），属 Elo 中性。

> **⚠️ 基线作废声明（C-20261022-191）**：上表"24 条快照 / 12 支球队"是在**队名身份未归一**的 Elo 上重放的——同一球队中英双线（实测 123/165 canonical 分裂、2026 赛季 95 队同季双线），部分回填赛果会落到错误分身。**窗口 C 执行 L3b 前必须按"身份归一后"重建 Elo 基线重做对拍，不得引用 24/12。**
