> 登记：C-20261019-146 | 性质：流程标准（只读诊断 + 重训窗口内执行，不动 serving）
> 依据：C-20261019-145（meta 共线性机制订正）、C-142/144（8 系列诚实版 + Elo 泄漏实锤）、C-007（方向/RPS 解耦）
> 铁律：本标准的一切「处理动作」只发生在**重训窗口**内的训练特征清单上；serving 模型与 selected_features pkl 一律不动。falsify first：任何特征剔除/合成须先出前后对照报告再入库。

## 〇、适用范围与两个输入面

本标准覆盖预测系统的两个独立输入面，分别诊断、分别验收：

| 输入面 | 对象 | 维度 | 消费方 |
|--------|------|------|--------|
| **A. 特征矩阵面** | `build_all_features(include_odds=True, ts_odds=True, consensus_odds=True)` 输出 ∩ `selected_features_*.pkl` | ~77 维 | XGBoost / LightGBM |
| **B. 融合输入面** | 5 子模型 × 主/平/客 15 概率 + dc_odds_fallback | 16 维 | Stacking meta（LR, C=1.0） |

核心原则：**数量堆叠 ≠ 有效独立**。A 面防「同族派生伪装多特征」（home_elo / elo_diff / elo_home_expected 同源）；B 面防「伪一致伪装共识」（5 个相关 0.9 的模型投票 ≠ 5 个独立视角）。

## 一、标准化诊断流程（S1→S5，全只读）

### S1 特征清单冻结与族标注
1. 加载 serving 特征清单：`assets/selected_features_*.pkl`（与 scaler 配套）。
2. 每个特征手工标注**信息源族**（首次执行后固化为 `reports/feature_family_map.csv`，后续只增量维护）：

| 族 | 判据（列名前缀/模式） | 已知成员示例 |
|----|----------------------|--------------|
| Elo 族 | `home_elo/away_elo/elo_*` 10 维 | elo_diff、elo_home_expected、elo_confidence… |
| 赔率快照族 | 即时赔率反演/隐含概率列 | implied_prob_*、wdl_open/close 派生 |
| 时序赔率族 | ts_odds 开关引入 | 赔率变动斜率/极差列 |
| 共识赔率族 | consensus_odds 开关引入 | 多公司离散度列 |
| 球员/阵容族 | 伤停计数、评分聚合列 | — |
| 赛果统计族 | 近 N 场战绩/进球滚动均值 | — |

> **族是冗余判定的第一筛**：同族特征天然共享信息源，高相关不意外；跨族高相关才是结构问题。

### S2 退化和缺失检查（先清垃圾再谈相关）
逐特征计算，任一命中即标记：
- 方差 < 1e-8（近常量）；
- 缺失率 > 30%（且非结构性缺失如「未开赛球队无滚动窗」）；
- 单一取值占比 > 99%。

### S3 两两相关矩阵（硬性规定全量产出，禁止抽样）
```python
import pandas as pd
from feature_utils import load_match_data_odds, build_all_features
df = load_match_data_odds(dedup=True)
X, _ = build_all_features(df, include_odds=True, ts_odds=True, consensus_odds=True)
Xf = X[feat_list]                       # feat_list 来自 selected_features pkl
corr_p = Xf.corr(method='pearson')      # 线性
corr_s = Xf.corr(method='spearman')     # 单调非线性（赔率类厚尾必看）
corr_p.to_csv('reports/feature_corr_pearson.csv')
corr_s.to_csv('reports/feature_corr_spearman.csv')
```
**判定阈值**（取 Pearson 与 Spearman 绝对值的较大者记 |r|）：

| \|r\| 区间 | 判定 | 动作 |
|-----------|------|------|
| < 0.4 | 通过 | 无 |
| 0.4 ~ 0.7 | 观察 | 进观察清单，不处理，重训窗复核趋势 |
| **≥ 0.7** | **高相关组** | 进第三节决策树，必须处理或书面豁免 |

> 0.7 阈值的依据：两特征共享方差 ≥50%（r²≥0.49），继续共存对 GBDT 只增加分裂竞争噪声、对 LR meta 直接制造共线性（C-145 勒芒场 +1.488 系数的成因）。

### S4 共线性结构诊断（VIF，逐特征一把算）
两两相关看不出的「多特征联合共线」（如 a+b≈c）用 VIF 兜底。不需要 statsmodels：
```python
import numpy as np
from sklearn.linear_model import LinearRegression
def vif_table(Xdf):
    Z = ((Xdf - Xdf.mean()) / Xdf.std()).values  # 标准化，防量纲干扰
    out = {}
    for j, c in enumerate(Xdf.columns):
        y = Z[:, j]; Xo = np.delete(Z, j, axis=1)
        r2 = LinearRegression().fit(Xo, y).score(Xo, y)
        out[c] = np.inf if r2 >= 0.999999 else 1.0 / (1.0 - r2)
    return pd.Series(out).sort_values(ascending=False)
```

| VIF | 判定 |
|-----|------|
| < 5 | 通过 |
| 5 ~ 10 | 观察（与同族高相关组并案复核） |
| **> 10** | **处理对象**，进决策树 |

补充（可选）：标准化后矩阵条件数 `np.linalg.cond(Z)` > 30 时，在报告头标注「全局共线性显著」。

### S5 伪独立识别（假交叉验证 / 泄漏型冗余）
冗余不只来自「两列像」，更来自「信息时间线被偷渡」。三项测试：

**S5-a 时点审计（k* 泄漏指纹，复用 C-143 已验证方法）**
对每个**随时间累积**的特征族（Elo、滚动战绩、时序赔率），验证其 as-of 口径：严格 `date < 比赛日` 重建特征值，与生产值对拍。判定沿用 C-143 门槛：**lag 指纹 k*≥+1 占比 > 20% → 泄漏系统性存在**，该族全部特征视为「伪独立」（它们携带未来信息，与标签的关系是假的）。

**S5-b 同族伪装独立检查**
族内特征两两 |r|≥0.7 的占比 > 50% → 该族实际有效维度 ≈ 代表特征数，在报告「有效维度」列登记（如 Elo 族 10 维 → 有效 ~3 维）。此数用于第六节「有效独立」验收，**不得**再用原始维度数对外宣称「77 维特征」。

**S5-c 时间反转测试（假交叉验证照妖镜）**
同一特征集，用「未来窗训练 → 过去窗验证」跑一遍。若反转成绩 ≈ 正向成绩 → 特征含时间无关的泄漏通道（典型：赛后回填）；正常模型反转成绩应**显著劣于**正向。所有验证切分必须 `train.date < val.date`；任何 shuffle K-fold 结果一律标注「伪独立风险，不作准」。

## 二、高相关特征组处理方案（重训窗口内执行）

### 2.1 处理决策树（|r|≥0.7 或 VIF>10 的组）

```
组内特征是否同族（同一信息源族）？
├─ 是 ──→ 保留 1 个代表，其余从训练特征清单剔除（不删物理列，serving 不受影响）
│         代表选取优先级：
│         ① 生产链已直接消费的（如 Elo 族保 elo_diff——CalcEngine 直接公式消费）
│         ② 业务语义最直接的（原始量 > 比率 > 派生变换）
│         ③ 缺失率更低 / 时序方差更稳的
│
└─ 否 ──→ 跨族高相关=结构问题，比较两特征与标签的单变量信息量
          （|point-biserial r| 或单特征 val AUC，一把 sklearn 算完）
          ├─ 信息量差 ≥ 0.05 ──→ 保留高者，低者剔除
          ├─ 差 < 0.05 且各有独立业务语义 ──→ 合成综合指标：
          │      · 同向指标 → 标准化后均值
          │      · 对立指标 → 差值（差值往往是最强特征，如 elo_diff 之于双 elo）
          │      · 多特征组（≥3）→ sklearn PCA(n_components=1)，
          │        须在报告注明 PC1 方差解释率（<60% 禁止合成，退回逐个保留评审）
          └─ 差 < 0.05 且无独立语义 ──→ 保留缺失率低者，另一个剔除
```

**处理后强制回路**：重跑 S3+S4 → 仍有 |r|≥0.7 或 VIF>10 → 继续决策树；两轮不收敛 → 整组提请人工评审（禁止第三轮机械迭代）。

### 2.2 独立视角划分原则（B 面 / Stacking 层）

「独立视角」的操作性定义——两个模型满足**全部**三条才算独立：
1. **信息源不重叠**：训练输入族交集为空（DC=赔率反演 vs Elo=赛果评分 ✓；XGB vs LGB 同吃一矩阵 ✗）；
2. **预测低相关**：同一测试窗内主胜概率序列 Pearson r < 0.85；
3. **误差不相关**：方向错误指示变量（错=1）的 phi 系数 < 0.5——「一起错」的模型对不是独立视角。

当前 5 模型的诚实定位（C-142/144 实测 + 本标准判定）：

| 模型对 | 视角关系 | 处置 |
|--------|----------|------|
| DC / Elo / 贝叶斯 两两 | 信息源正交，独立视角 | 维持 |
| **XGB / LGB** | 同族双引擎（特征矩阵相同），误差相关天然 0.7~0.9 | **不视为两个独立视角**；固定权重合计 55% 为已知集中度，台账在案；其价值=算法多样性（正则强度 vs 叶子生长策略），不是信息多样性 |
| 任意 / 市场去水 | 市场是对照基准，**永远不入 stack** | 维持（防 DC 与市场互为回声） |

### 2.3 meta 输入面（16 维）的共线性特殊条款
- meta 的 15 个概率单元受 5 个「和为 1」约束，有效自由度 10（C-145）——**禁止**对 meta 系数做「信任度」解读；
- meta 层**不做**特征剔除（概率单元的冗余由 LR 正则 C=1.0 吸收），只做基模型视角验收（2.2）；
- 基模型校准/特征变更 ⇒ meta 必须同窗重训（C-145 耦合纪律，优先于本标准一切处理动作）。

## 三、效果验证与质量验收（V1→V4，全过才算完）

### V1 置信度真实性（去冗余前后对照，同一 val 时间窗）
- 口径：C-142 分桶校准（0.4-0.5 / 0.5-0.6 / 0.6+ 桶：预测均值 vs 实际命中）+ RPS + LogLoss；
- **通过**：各桶 |实−预| 不恶化，且 RPS、LogLoss 均不升；
- 允许形态：高置信桶样本占比下降 + 桶校准改善（去冗余挤掉的是虚高置信，这是预期收益不是损失）。

### V2 鲁棒性（输入扰动测试）
对 val 集全部数值特征加 ±5% 高斯噪声，蒙特卡洛 100 次，度量输出概率平均 |Δp|：
- **通过**：去冗余后 |Δp| ≤ 去冗余前（目标下降 ≥10%，共线性降低 ⇒ 系数/分裂对噪声的敏感度下降）；
- 恶化即回滚该轮特征处理。

### V3 分歧真实性（反伪一致）
报告「分歧度等级」（三向概率标准差均值，生产口径见 generate_unified_report）必须与独立视角数一致：
- 计算 5 子模型两两预测相关（2.2 节第 2 条）；
- **≥3 对两两 r>0.85** 且分歧度等级=「低」→ 报告须标注「**伪一致风险**」，禁止解读为「模型共识强」；
-  stacking 输出方向与 5 模型多数票一致率 > 95% 持续一个重训窗 → meta 未学到分歧形态（形同虚设），触发 meta 复核。

### V4 无泄漏复验
处理后的特征清单重跑 S5-a k* 指纹：**k*≥+1 占比必须 = 0**（C-144 修复后基线）；时间反转测试成绩必须显著劣于正向。

## 四、执行文档

### 4.1 特征冗余自查清单（每次重训窗逐项打勾）
- [ ] selected_features pkl 与 scaler 版本配对无误
- [ ] 族标注表 feature_family_map.csv 无未标注新列
- [ ] S2 退化/缺失清单零新增（或已书面豁免）
- [ ] Pearson + Spearman 双矩阵已落 reports/（全量，非抽样）
- [ ] |r|≥0.7 组全部过决策树，豁免项有书面理由
- [ ] VIF>10 清零或书面豁免
- [ ] Elo 族等时序族 k* 指纹 = 0
- [ ] shuffle CV 结果未作为任何结论依据
- [ ] XGB/LGB「同族双引擎」集中度在报告显式标注
- [ ] 有效维度数（族代表口径）已更新，未再宣称原始维度数
- [ ] 基模型侧任何变更已触发 meta 同窗重训评审（C-145）
- [ ] V1~V4 四项验收报告落盘

### 4.2 相关性检查操作步骤（标准七步）
1. `load_match_data_odds(dedup=True)` → `build_all_features(三个 True)` 重建矩阵；
2. 按 selected_features pkl 取列、按 S2 清退化列；
3. 标准化（z-score）→ 双相关矩阵落 CSV；
4. 提取 |r|≥0.7 对 → 按族聚合成「高相关组」；
5. VIF 全表计算，>10 并入组清单；
6. 组清单逐组过 2.1 决策树，产出《处理决议表》（组号/成员/族/|r|/VIF/决议/代表或合成公式/理由）；
7. 处理后再跑 3-4 步复验，直至收敛（两轮上限）。

### 4.3 处理决策树
见 2.1（同族保代表 → 跨族比信息量 → 语义双留则合成 → 合成受限 PC1≥60% → 两轮不收敛转人工）。

### 4.4 最终验收判定条件（G1~G6，全绿才准入库）
| 门 | 条件 |
|----|------|
| G1 | 相关矩阵无未处理/未豁免的 \|r\|≥0.7 组 |
| G2 | VIF ≤ 10（或书面豁免） |
| G3 | S5 三项伪独立测试全过（k*=0、族有效维度已登记、反转测试显著劣化） |
| G4 | V1 置信度：桶校准不恶化 + RPS/LogLoss 不升 |
| G5 | V2 鲁棒性：扰动 \|Δp\| 不高于处理前 |
| G6 | V3 分歧真实性：无未标注的伪一致；meta 多数票一致率 < 95% |

任一红灯 → 本轮特征处理整体回滚，问题组转人工评审。**不允许**「先上线观察」。
