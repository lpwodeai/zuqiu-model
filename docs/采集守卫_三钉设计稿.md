## 1. 锚点（"赛程在场"的唯一来源）

- 主锚：`scripts/export_sporttery_snapshot_csv.py::fetch_matches()` — 只读、独立于 500、带 `matchTime` 与 canonical `match_id`。
- 副锚：`odds500_match`（`status=1`），仅作交叉校验，**不作主锚**（避免自指：被守卫源不得当尺子）。
- 归组键统一用 **`businessDate`（竞彩销售日）**，不用开球日历日。
- 两锚不一致 → `anchor_conflict`（不直接 fatal，优先怀疑赛程本身）。
- 锚不可用（竞彩接口失败）→ `anchor_unavailable` **单独 fatal**，禁止静默放行。

## 2. 三条守卫判据

### L1 采集器零行 → 非 0 退出
- 证据 = 采集器自身运行时的落库行数（**不需要台账**，day-1 即全功能）。
- 依赖锚点判"应采"：应采且零行 → 非 0；不应采（休赛期/国际比赛周）零行 → 正常退出。
- 观察类步骤（0a-4/0a-5/2c/2d/2e）一并纳入，不再只写看板。

### L2 窗口覆盖缺口（与 L1 合并为一条告警）
- 判据：`expected_dates − actual_dates ≠ ∅`，一条告警，附明细（源/联赛/日期）。
- **粗模式（day-1）**：证据 = 各源现有表的 `last_data_date`（表级）。
- **精模式**：证据 = `collection_runs` 台账（源 × 联赛 × 日期 × 采集时刻 × 行数）。
- **依赖写死**：L2 精模式上线 = C-201 之后；C-200 不对精精度作承诺。

### L4 批次级预期刷新（与 O4 同段实现）
```
expected_last_refresh(match) = max{ t ∈ 当日计划批次 : t ≤ kickoff(match) }
告警 = 该场 prematch_data_quality.generated_at 最大值 < expected_last_refresh − 容差(30min)
```
- 证据 = `prematch_data_quality.generated_at`（我方采集/报告时刻），**禁用 `wdl_history.timestamp`**（竞彩改价时刻，不改价即无行）。
- 计划批次从配置表读取（12:00 / 20:00），配置与实际计划任务每周自检一次，偏差即告警；不现场解析 schtasks XML。
- O4（注册数 vs 报告数）同段实现，口径独立、不与 L4 共用判据。

## 3. 四个钉（设计约束）

- **钉 1 精度承诺边界**：L1 day-1 全功能；L2 day-1 粗模式；L2 精模式依赖 C-201。设计稿与提案均不得把 L2 精度写成 C-200 的交付物。
- **钉 2 评估时点事件驱动**：挂看门狗 23:55 趟；若 `finished_at` 为空 → 记 `pending` 不判，由 01:10 趟兜底判定。不设 23:30 墙钟（0a-3 特征重算 53 分钟先例，链晚收尾会把在跑批次判成漏采）。
- **钉 3 中文键写入路径挂 C-190 L1 范围扩展**，不另立项。注记：C-190 根因是"日期键分裂"，本发现是"中英键分裂"，同属写入归一缺失；窗口 C 修 L1 时一并强制 canonical 键。
- **钉 4 销售日归组**：00:00–03:00 开球场次（如 周六022 那不勒斯 2026-10-25 00:00）按销售日 10-24 归组；按开球日历日归组会让次日批次集为空 → 误报或漏判。

## 4. shadow → fatal 门槛

- shadow 3–5 天，只写 `STATUS.md` 守卫观察区，**发 0 告警**。
- 产出**缺口日历**（哪天缺哪批、缺几场）；已知结构性缺口（500 晚间刷新无触发器）进**基线白名单**。
- 转 fatal 条件 = **新增缺口为 0**（非"误报归零"）。
- 上线后只看"新增缺口"，防止把已知问题当新问题反复喊。
