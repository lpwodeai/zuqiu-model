## 一、设计目标与约束

### 1.1 目标

- 构建**五大联赛（英超/西甲/意甲/德甲/法甲）赛果预测全栈系统**，核心交付物为高质量**概率预报**（WDL 胜平负 / 让球 / 比分 / 总进球四任务）。
- 主模型目标 = **高质量概率预报**（RPS、可靠性校准 ECE），**不以投注 ROI 作为训练与验收目标**（实验红线 §15.3）。
- 打通「采集 → 特征 → 训练 → 推理 → 预测/报告 → 赛后复盘 → 知识库 → 重训」**闭环**。

### 1.2 约束

| 约束 | 内容 |
|------|------|
| 双运行时 | **Python 训练离线侧 + Node.js 推理在线侧**，训练产物双写 pkl（Python）+ `*_export.js`（Node） |
| 单一配置源 | `config.yaml` 全局配置单一来源（D3），Node 运行时读 yaml，禁止 JS 硬编码阈值 |
| 数据隔离 | `odds.db`（训练库，1.6GB+）与 `five_leagues.db`（生产业务库）分离 |
| 时序防泄漏 | 训练/回测/校准一律 `TimeSeriesSplit` + 无 shuffle |
| 幂等写库 | `INSERT OR IGNORE` + `UNIQUE` 约束；连接 `busy_timeout=5000` |
| 队名归一 | 入库/查询统一 `normalize_team_name()` / `TEAM_NAME_MAP` |
| 路径动态 | 所有脚本用 `Path(__file__).resolve().parent` 定位，禁止硬编码盘符 |

### 3.2 赔率时序存储（4 表 + 桥接）

| 表 | 覆盖场次 | 对齐率 | 玩法字段 |
|----|---------|-------|---------|
| `wdl_history` | ~12,575 | 98.3% | `win_a`(主胜) / `draw` / `win_b`(客胜) |
| `handicap_history` | ~13,125 | 98.3% | `hcp_win` / `hcp_draw` / `hcp_lose`（让球） |
| `total_goals_history` | ~13,126 | 98.3% | `goals_0` ~ `goals_7_plus` |
| `score_history` | ~13,122 / 81.6 万行 | 63.8% | `score` + `odds`（正确比分） |

- 四通道对齐（`feature_utils.build_match_alignment`，C-20260920-025 升级）：通道0 history.match_id 与 matches.match_id 直接等值（覆盖中文赛季 ~71%）→ 通道1 `match_id_mapping` 桥表 → 通道2 history 表自带 `match_id_en` 列直连 → 通道3 中→英名称兜底（解析中文键日期+队名，经 `export_team_name_map` 翻译，按标准中文名双等值 **或** 翻译 token 被官方队名 token 覆盖：等值/前缀/编辑距离≤2，日期窗口 ±1 天，候选唯一才写入）。通道3 专门覆盖 26-27 赛季时序表 match_id 全为中文键、match_id_en 为空且竞彩官方日与比赛当地日差 1 天的场景。
- 6 种桥接策略（按优先级）：`cn_to_en → substring → direct → sofascore → fuzzy_date → date_tolerance(±1天)`。

### 3.3 Understat xG 三表（`understat_schema.md`）

- `understat_match_team_stats`（比赛级，主键 `match_id`）：比分/xG/赛前 `forecast_w/d/l`。
- `understat_player_xg`（球员级，复合主键 `(match_id, player_id)`）：xG/xA/`xg_chain`/`xg_buildup`（Understat 独有）。
- `understat_shots`（射门级，主键 `shot_id`）：坐标/部位/情况/结果，用于射门地图与进球质量。

### 3.5 数据质量审计（`sofascore_quality_audit.py`，D2 环节）

## 五、模型/训练层

### 5.1 WDL 主模型（生产链路 `train_models.py`）

- **Stacking = 5 基础模型 + LR meta-learner**：Dixon-Coles（泊松/DC）+ Elo + XGBoost + LightGBM + 贝叶斯层级（Baio-Blangiardo HBM）。
- 训练流程：`load → 质量门禁 → build_all_features(254维) → 样本权重(异常3.0/双误4.0 + L3知识库 + 人工修正1.2) → TimeSeriesSplit(5) → XGB/LGB → Platt校准 → 平局后处理校准(召回≥0.28约束) → 分层评估 → repro_snapshot落盘assets（C-20260926-094 方案B 已去MLflow） → 双写 pkl + *_export.js`。
- 当前超参（config.yaml `model.*`，Optuna 搜索）：XGBoost `max_depth=4, min_child_weight=13, gamma=4.956`（反过拟合）；LightGBM `max_depth=3, num_leaves=202, min_data_in_leaf=23`。
- **OOF RPS = 0.1989**（holdout 第5折 RPS = 0.2024，优于旧版 0.2043；Stacking 优于固定权重 0.2024）。
- **LR meta-learner 运作原理**：
  - 两层结构——第一层 5 基模各出主/平/客概率，拼成 **15 维概率特征 + 1 维 `dc_odds_fallback` 标志 = 16 维特征向量**（命名 `模型名__win/draw/lose`，C-20260920-030）；第二层逻辑回归对其加权求和后 softmax，输出最终三向概率。
  - 权重**学自历史 OOF（折外）预测而非人工拍定**：训练入口 `scripts/train_stacking_meta.py`，meta 只在基模没见过的折外样本上训练，防止"自评自学"虚高。
  - **OOF 与 serving 严格同链路**（C-20260920-030）：DC 在 OOF 中同样走赔率→λ（`calc_lambda_from_odds`）→A-002→联赛 ρ DC（旧版用联赛场均 λ，与 serving 不同源、极端 DC 成 OOD）；缺赔率的历史样本回退联赛均值 λ 且 `dc_odds_fallback=1`（当前 OOF 12620 场中赔率 DC 4500/兜底 8120），serving 正常比赛恒传 0。
  - **三级降级链**：LR meta-learner（≥2 基模可用）→ 固定权重 Stacking（DC 0.30/XGB 0.30/LGB 0.25/Elo 0.15/贝叶斯 0.20）→ 赔率隐含概率（可用基模 <2）。
  - Train/Serve 契约：推理侧 meta 特征必须与训练时 `feature_names` 一一对应（见 §六 `apply_stacking_meta_learner`，支持 `extra_features` 传入标志特征）；新增/删减基模须重训 meta，禁止只改一侧。

- **平局阈值决策（C-20260926-095，15,135 场 OOF 全量实测）**：
  - 现象：**Stacking 原始 argmax 天然强反平局**——LR meta 平局召回仅 **0.6%**、固定权重 0.9%（对比单模型 XGB/LGB 原始召回 15~17%）；平局在 meta 16 维输入中被主/客胜维度压制。
  - 自适应搜索（约束平局召回 ≥0.28 后最大化准确率）：LR meta **F=1.42**（acc 0.4998，比 argmax 损失 **2.38pp**）；固定权重 **F=1.22**（acc 0.5014，损失 2.10pp）。
  - **决策：生产保持 `draw_threshold_mode: argmax`**（LR meta acc=0.5236 / RPS=0.2005，已是全局最优；强行提平局召回得不偿失）。
  - 单模型训练报告推荐的 F=1.45/1.50 **不可直接套用到 Stacking**（两口径概率分布完全不同）；若未来业务强制提升平局召回，**优先走固定权重路径（F=1.22）**，其调整幅度与准确率损失均小于 LR meta（F=1.42）。
  - 联赛特异性（LR meta，若启用）：西甲 F=1.37（损失 1.0pp）、意甲 F=1.43（损失 0.6pp）可单独启用；英超 F=1.49、德甲 F=1.45、法甲 F=1.44（法甲损失 2.4pp 且原始 acc 最低，**不建议启用**）。

### 5.2 各子模型

#### 5.2.1 WDL 五个基础子模型（C-20260919-022 补录）

> 全部产出 `{win, draw, lose}` 三向概率，供 LR meta-learner Stacking。前 3 个为**运行时轻量计算**，后 2 个为 **254 维特征 ML 模型**。

**子模型可观测性与口径注释**（C-20260919-022）：

1. **XGB 缺失三层哨兵**（只告警，不改概率/标签）：
   - 推理层：WDL 决策后检测 `sub_probs['xgboost']` 缺键或类型非法 → 日志 `🚨 WDL模型·哨兵`（含可用 n/5）；
   - 报告层：子模型表分歧度行后内联 🚨 块，指明已降级为 n 模型融合、查日志定位；
   - 批次层：一批结束后控制台汇总所有 XGB 未产出的场次。
   - 设计原因：「—」有假性缺失（float32 渲染，C-020 已根治）与真性缺失（pkl/scaler/两级取数/推理异常）两种成因，哨兵保证真性缺失必然显形。
2. **EV 方向 ≠ 概率方向自动注释**：§一推荐卡与 §6.2 决策卡两处，当 EV 推荐方向与 WDL 概率方向相反时自动插入 ℹ️ 解释块——概率层答「谁最可能赢」，EV 层答「押谁的赔率长期划算」（P×赔率>1），明确标注「小概率高赔率冷门的小仓位价值提示，不是模型改判」。三套口径（模型输出/EV 规则/展示标签）严格分离，禁止互相覆盖。
3. **「n/5」计数口径**（C-20260919-023）：所有 n/5（§二标题、§十八元数据、XGB 哨兵）只数 `STACKING_META_MODELS` 五键。运行时 sub_probs 另有 `poisson`、`ssm` 两个早期辅助参考源（每场计算并记日志，但不进 LR meta、不进报告子模型表），数进它们会错误显示 7/5。

  - **train/serve 同源**：`upset_factor_engine.compute_upset_risk_score()` 为纯函数，训练侧（train_models）与推理侧（prediction_core）共用同一函数；数据缺失时返回 `MISSING_SCORE=0.5` + `upset_data_missing=1` 标志特征（禁止静默默认，project_memory 硬约束）
- **三套加权去重叠加（C-030 改造）**：`train_models.py` 主流程改为三套独立计算 + `np.maximum` 取 max：
  - `anomaly_w = create_sample_weights(df)`（绝对权重，1.0/3.0/4.0/5.0，C-050 后叠加 upset_risk_score 加成）
  - `l3_w = apply_l3_sample_weights(df)`（相对增量，从 1.0 起算，×= 1.2 等）
  - `corr_w = apply_human_correction_weights(df)`（相对增量，从 1.0 起算，×= 1.2 等）
  - `sample_weights = np.maximum(np.maximum(anomaly_w, l3_w), corr_w)`
  - 同一样本若被多套命中，取 max（不再 ×= 累乘导致权重爆炸）；加权日志分别记录来源到 `logs/knowledge_hit.jsonl`（project_memory 硬约束）
