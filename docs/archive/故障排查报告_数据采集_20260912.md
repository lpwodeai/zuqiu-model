## 三、根因分析

### 3.1 500.com 数据（双重根因，主因是「字段已采集但为空」+「反爬升级」）

**根因 A：无定时任务触发采集，数据从不刷新。**
- `schtasks` 查询显示，系统仅有 5 个模型相关任务：`ConceptDrift`、`P0ELiveTrial`、`P1BShadow`、`PostMatchReview`、`PrematchReport_2030`。
- **没有任何**任务运行 `collection/final_500_collector.py`。
- 唯一的赛前任务 `TraeCode_PrematchReport_2030` 执行 `run_prematch_2030.ps1`，该脚本：
  1. 只刷新竞彩时序赔率（`sporttery_live_collector.py`）；
  2. `generate_unified_report.py` 生成报告；
  3. `send_report_email.py` 推送。
  - **完全没有 500.com 采集步骤**。且该脚本 `$reportDate` 被硬编码为 `"2026-08-30"`（已过期）。

**根因 B（更严重，且为真正「现在不行了」的原因）：500.com 部署了腾讯云 EdgeOne 两层人机防护，`requests` 采集器被彻底拦截。**
- 实测（2026-09-11 复现）`https://odds.500.com/fenxi/ouzhi-{fid}.shtml` 返回 `Server: TencentEdgeOne`，两种表现：
  1. **第一层 JS 挑战**：HTTP 200 但正文仅 ~988 字节，为混淆脚本 `<script>function a(a){..._0x649a...}`，计算后写入 `__tst_status` 与 `EO_Bot_Ssid` 两个 cookie 并自动刷新。
  2. **第二层「Security Verification」人机验证页**：带 cookie 重放后返回 ~2.1KB 的 `<title>Security Verification</title>` 页，外链腾讯验证脚本（`https://ca...`），需**真实浏览器完成滑块/勾选验证**，无法离线计算绕过。
- 实测还发现：**高频探测会触发 EdgeOne 升级防护**——连续多次请求后，连第一次请求都直接命中「Security Verification」页（跳过 JS 挑战），IP 被临时加重防护。
- `final_500_collector.py` 基于 `requests` + `BeautifulSoup`，**无法执行 JS 也无法完成人机验证**，`parse_ouzhi` 只能得到空结果 → 写入空壳行（与 2.2 的空数据吻合）。此前（08-26 前）该站点尚无非 JS 拦截，故技能文档记录的 1.8 万行历史数据属实；**是站点在近期新增了 EdgeOne 防护导致「现在不行了」**。

### 3.2 SofaScore 数据（仅西甲缺失，根因是赛程未注册）

- `sofascore_pre_match_features.py` 的特征生成，依赖 `fbref_match_mapping` 中 `fbref_match_url LIKE '%sofascore%'` 的比赛行（见 `load_sofascore_matches()`）。
- 实测 `fbref_match_mapping` 西甲最新仅到 **2026-09-08（第 4 轮）**，**第 5 轮（09-12/09-13）赛程未注册**，因此「塞维利亚 vs 巴伦西亚」无对应行，特征无法生成。
- 注册赛程的入口是 `final_sofascore_collector.py`（`collect_league → collect_single_event → write_match_to_db` 会对赛程做 `INSERT OR IGNORE`），但该脚本同样**没有每日赛前定时任务**，西甲第 5 轮枚举被遗漏。
- 其他 3 场（德甲/意甲/法甲 09-12）及西甲之外的 09-13 场次赛程已注册，故特征已生成。

### 3.3 附带缺陷：数据完整度计算掩盖了 500.com 缺失

- `generate_unified_report.py` 第 457 行：
  ```python
  comp_500 = 1.0 if extra["500"]["ouzhi"] is not None else 0.0
  ```
  仅判断数据行**是否存在**，未判断是否含真实赔率。空的 ouzhi_summary 行（company_count=0）被当作「完整 = 1.0」。
- 结果：前 3 场完整度被高估为 **83%**（实际 500.com 维度全空），报表「八、百家欧指」显示「公司数 0」但完整度未下降，掩盖了 500.com 数据丢失。

### 3.4 巴伦西亚客场评分异常（2.80）的深层根因

初次报告判定「塞维利亚 vs 巴伦西亚」客队评分 2.80 属「球员样本稀疏」，**该结论已作废**。二次核验定位到真实根因：

- 聚合脚本 `sofascore_pre_match_features.py` 的 `aggregate_team_history()` 中，`sofa_rat_5g` 用「首发球员 rating 加权均值」计算，缺失 rating 的球员走 `fillna(0)`：
  ```python
  features["sofa_rat_5g"] = float(
      (starters["rating"].fillna(0) * sw).sum() / sw.sum()
  )
  ```
- 巴伦西亚近 5 场中，有 **3 场**在 `match_player_stats` 里 `rating` 全缺（首发 11 人均无评级）：
  | event_id | 比赛 | 补采前首发有评级 |
  |----------|------|:---------------:|
  | 16416325 | 09-06 巴伦西亚 vs 巴塞罗那 | 0/11 |
  | 16416291 | 08-31 拉科鲁尼亚 vs 巴伦西亚 | 0/11 |
  | 16421049 | 08-26 巴伦西亚 vs 皇家贝蒂斯 | 0（无行） |
- 这 3 场的评级被 `fillna(0)` 归零后，加权均值 `(7.0 × 2 场权重) / (5 场权重) ≈ 2.80`，恰好复现 `sofa_rat_5g_away = 2.7965`。
- **根因**：这 3 场比赛在 SofaScore 赛后采集时，`rating` 字段未落入 `match_player_stats`（可能因采集时比赛状态未 final、或 lineups 接口未带球员统计），而特征重建阶段未做「rating 覆盖率」校验，直接按 0 参与加权。

**修复**：对 3 场执行 `collect_single_event`（`final_sofascore_collector.py`，`INSERT OR REPLACE` 幂等补采评级），删除该场旧特征行后重跑 `incremental_sofascore_features.py`，修正后 `sofa_rat_5g_away = 6.54`。详见 §五。

**500.com 补采（已完成，最终解法）**：
1. HTTP 层 `requests` → **`curl_cffi`**（`Session(impersonate="chrome")`）——真正根因不是「不能执行 JS」，而是 `requests` 的 TLS 指纹（JA3）与真实浏览器不一致，EdgeOne 据此识别出「非真人浏览器」并重降级验证。curl_cffi 模拟真实浏览器指纹，配合 Cookie 即可通过。
2. Cookie 需含三层凭证（缺一不可）：
   - `__tst_status`（JS 挑战值，实为固定常量 `3534236787#`）
   - `EO_Bot_Ssid`（会话 token）
   - **`EO-Bot-Captcha-Token`**（勾选复选框后由 Tencent CAPTCHA 写入的 ticket，**唯一真正放行凭证**）
3. **User-Agent 必须与导出 Cookie 的浏览器一致**——`EO-Bot-Captcha-Token` 与 UA 绑定；采集器默认 UA 已同步为 Edge 152，也可在 `cookies_500.json` 加 `"__user_agent"` 键覆盖。
