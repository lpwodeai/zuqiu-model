# 五大联赛预测模型 v2.0 全栈架构系统性评估报告

> **评估日期**: 2026-08-12  
> **评估版本**: v2.0 (release/v2.0)  
> **评估范围**: 技术缺陷 / 性能瓶颈 / 数据质量 / 算法局限 / 功能短板 / 2026-2027赛季适配

---

## 执行摘要

本报告对五大联赛足球预测模型进行了全面的系统性评估。当前系统在**胜平负预测（T-005）**和**比分预测（T-006）**两个核心任务上已具备生产部署能力，但存在以下关键问题：

| 维度 | 严重程度 | 核心问题 |
|------|----------|----------|
| 技术缺陷 | 🔴 高 | `eval()` 解析模型、硬编码映射、无类型检查 |
| 性能瓶颈 | 🟡 中 | SQLite 并发写锁、模型加载阻塞、无批量推理优化 |
| 数据质量 | 🔴 高 | 无 2026-2027 赛季数据管线、伤病/转会数据缺失 |
| 算法局限 | 🔴 高 | T-005 仅 51.24% CV 准确率（三分类）、赛季冷启动无方案 |
| 功能短板 | 🔴 高 | 让球/总进球/比分预测未形成独立API、无实时更新 |

**结论**：当前系统可用于 2026-2027 赛季的**有限场景预测**（已知球队、有历史数据的比赛），但无法满足完整赛季预测需求。需按优先级路线图进行改进。

## 第一章：技术缺陷分析

### 1.1 代码质量问题

#### 🔴 CRITICAL: `eval()` 安全漏洞

**位置**: [prediction-service.js#L241](file:///h:/zuqiu/五大联赛专属模型/五大联赛专属模型/server/services/prediction-service.js#L241-L241)

```javascript
eval('this.xgbModel = ' + xgbMatch[1]);
eval('this.lgbModel = ' + lgbMatch[1]);
eval('this.featureScalerParams = ' + scalerMatch[1]);
```

**风险**: 若模型导出文件被恶意篡改，可执行任意代码。建议改用 `JSON.parse()` 或 `vm2` 沙箱执行。

#### 🟡 HIGH: 硬编码球队映射

**位置**: [prediction-service.js#L284-L351](file:///h:/zuqiu/五大联赛专属模型/五大联赛专属模型/server/services/prediction-service.js#L284-L351)

`getEnglishTeamName()` 使用 60+ 条硬编码映射。当 2026-2027 赛季有升班马或球队更名时，映射表将失效。

**对比**: Python 端 [feature_utils.js#L13-L100](file:///h:/zuqiu/五大联赛专属模型/五大联赛专属模型/scripts/feature_utils.py#L13-L100) 有 193 条 TEAM_NAME_MAP，Node.js 端仅 60 条，两端映射不一致。

#### 🟡 HIGH: 脚本数量失控

`scripts/` 目录下有 **200+ 个 Python/JS 脚本**，其中大量为一次性调试脚本（`_debug_*`, `check_*`, `analyze_*`, `import_*`）。缺乏模块化分层，维护成本极高。

#### 🟢 LOW: 无 TypeScript

Node.js 后端全部使用 JavaScript，无类型检查。预测逻辑复杂（6 模型 Stacking），类型错误风险高。

### 1.2 架构设计缺陷

#### 🔴 CRITICAL: Node.js ↔ Python 模型割裂

```
训练链路: Python (train_models_v2.py) → .pkl 模型文件 → 导出为 .js
预测链路: Node.js (prediction-service.js) → 加载 .js → 用 JS 重实现预测逻辑
```

**问题**:
- Python 训练的模型需要手动导出为 JS 格式，存在精度损失风险
- 特征工程逻辑在 Python 和 JS 中重复实现，难以保持一致
- 任何模型更新都需要手动同步 Python 和 JS 两端

#### 🟡 HIGH: 单数据库设计

三个 SQLite 数据库文件：
- `five_leagues.db` — 主数据库（matches, teams, leagues）
- `odds.db` — 赔率数据库（wdl_history, handicap_history, score_history）
- `odds_timing.db` — 时序赔率数据库

**问题**: 无外键约束，跨库 JOIN 无法在数据库层面保证一致性。匹配依赖 `match_id_mapping` 桥接表。

#### 🟡 HIGH: 无消息队列

所有服务间通信通过函数调用或直接数据库访问。无异步解耦，模型重训练会阻塞 API 响应。

### 1.3 安全漏洞

| 漏洞 | 位置 | 风险 |
|------|------|------|
| `eval()` 执行模型代码 | prediction-service.js:241-255 | 远程代码执行 |
| 无输入校验（部分路由） | predictions.js:27-46 | SQL 注入 |
| JWT secret 硬编码风险 | auth middleware | 凭证泄露 |
| Redis 密码为空默认 | cache-service.js:8 | 未授权访问 |
| CORS 仅限制 origin | index.js:54 | CSRF 攻击 |

## 第二章：性能瓶颈分析

### 2.1 并发瓶颈

#### 🟡 单进程 Cluster 写入锁

**位置**: [database/index.js#L32](file:///h:/zuqiu/五大联赛专属模型/五大联赛专属模型/server/database/index.js#L32-L32)

```javascript
this.db.pragma('busy_timeout = 5000');
```

`busy_timeout=5000ms` 意味着当 8 个 Worker 同时写 SQLite 时，最坏情况需等待 5 秒。经 Cluster 模式压测，并发 1000 时已出现 1.43% 错误率。

**建议**: 引入写队列（Write-Behind Log）或迁移至 PostgreSQL/MySQL。

#### 🟡 模型加载阻塞

**位置**: [prediction-service.js#L236-L263](file:///h:/zuqiu/五大联赛专属模型/五大联赛专属模型/server/services/prediction-service.js#L236-L263)

`loadTrainedModels()` 使用 `fs.readFileSync()` + `eval()` 同步加载所有模型。每次热更新都会阻塞 Worker 进程。

### 2.2 IO 瓶颈

#### 🔴 全表预加载

**位置**: [t006_score_predictor_v4.py#L165-L203](file:///h:/zuqiu/五大联赛专属模型/五大联赛专属模型/scripts/t006_score_predictor_v4.py#L165-L203)

```python
def preload_all_wdl(conn):
    df = pd.read_sql_query('SELECT match_id, win_a, draw, win_b, timestamp FROM wdl_history', conn)
```

T-006 比分预测在回测时将 **全表 WDL 赔率**加载到内存。当 2026-2027 赛季数据量翻倍时，内存占用将线性增长。

#### 🟡 无索引优化

SQLite `five_leagues.db` 的 `matches` 表缺少关键索引：
- 无 `(competition_name, date)` 复合索引
- 无 `(home_team, away_team)` 复合索引
- 查询全表扫描风险高

### 2.3 推理性能

| 指标 | 当前值 | 瓶颈 |
|------|--------|------|
| T-005 单场推理 | < 10ms | 可接受 |
| T-006 单场推理 | 0.022ms（批处理） | 可接受 |
| 模型热更新 | 阻塞 ~100ms | 影响实时预测 |
| 批量预测 | Promise.all 串行 | 无批处理优化 |

### 2.4 内存瓶颈

- **Assets 文件夹**: 200+ 模型资产文件（训练日志、中间模型、历史权重），累计数 GB
- **无清理策略**: 每次训练生成新文件，从不清理旧资产
- **Redis 缓存**: 配置了但默认连接失败时退化为内存缓存，Worker 重启后缓存丢失

## 第四章：算法局限性分析

### 4.1 T-005 胜平负预测

#### 🔴 核心瓶颈：CV 准确率仅 51.24%

```
基线（随机三分类）: 33.3%
T-005 LGB CV:      51.24% (↑ 17.9pp)
T-005 XGB CV:      51.14% (↑ 17.8pp)
行业基准（奥彩）:   55-60%
```

**根因分析**:

1. **赔率特征占主导**: 模型 60+% 的特征是赔率衍生特征（凯利指数、变化率等），赔率本身已包含市场定价的核心信息。模型更多是"复刻"赔率而非超越赔率。

2. **缺乏比赛级特征**: 无首发阵容、无球员 xG、无伤病、无主场裁判等比赛级信息。所有特征都是赛前聚合统计，粒度太粗。

3. **114 维特征中有冗余**: D-017 特征选择从 85 维精简到 60 维，但生产模型使用 114 维，包含冗余特征。

#### 🟡 概率校准失败

D-016 实验证明 Platt Scaling 和 Isotonic Regression 均无法改善小数据集上的概率输出。这意味着模型输出的概率分布不可信，置信度越高的预测不一定越准确。

### 4.2 T-006 比分预测

#### 🟡 Poisson 分布假设局限

**位置**: [t006_score_predictor_v4.py#L205-L258](file:///h:/zuqiu/五大联赛专属模型/五大联赛专属模型/scripts/t006_score_predictor_v4.py#L205-L258)

```
lambda_total = score_implied_total  # 从比分赔率隐含
lambda_home = lambda_total * home_ratio
lambda_away = lambda_total * away_ratio
```

**局限**:
1. **独立性假设**: Poisson 假设主客队进球独立，但实际存在联动（如红牌影响双方进球率）
2. **均值回归**: λ 裁剪到 [0.1, 6.0] 区间，极端比分（0-7, 7-0）无法预测
3. **赛季初失效**: 无历史数据的赛季初比赛，score_implied_total 不可靠

#### 🟡 Dixon-Coles 修正参数全局共享

Dixon-Coles ρ 参数用于修正进球相关性，但当前实现：
- 仅按联赛分档（5 个联赛各一个 ρ）
- 不考虑比赛特殊性（德比战、保级战、欧冠预选赛等）
- ρ 网格搜索范围 [-0.40, 0.05]，最优值可能不在此范围

### 4.3 特征工程局限

#### 🔴 无实时更新特征

所有特征（Elo 评级、球队历史统计、赔率变化率）都是**赛前预计算**的，比赛当天不更新：
- 球队近期状态（近 5 场）基于 T-14 天数据
- Elo 评级基于历史快照，不考虑当前赛季状态
- 赔率特征冻结在赛前某一时刻

#### 🟡 无比赛级特征

特征工程仅限于球队聚合统计，缺少：
- 首发阵容（首发中锋 vs 替补中锋影响巨大）
- 球员伤病（核心球员缺阵导致 xG 下降 30%+）
- 历史交锋（H2H 记录，当前仅部分）
- 裁判风格（红黄牌率影响红牌点球率）
- 赛程密度（双线作战影响体能）

#### 🟢 数据泄露防护到位

D-009 特征时序分离机制已验证有效。21 项赛后特征黑名单（homeGoals, awayGoals, homeXg 等）确保无数据泄露。

## 第六章：2026-2027 赛季预测能力评估

### 6.1 赛季场景能力矩阵

| 赛季阶段 | 数据可用 | 预测可靠性 | 关键缺失 |
|----------|----------|------------|----------|
| **季前准备** | 仅有历史数据 | 🔴 低 | 无转会/伤病/季前赛数据 |
| **赛季初 (1-5轮)** | 部分新数据 | 🔴 低 | 球队状态未建立，升班马无历史 |
| **赛季中 (6-25轮)** | 充足数据 | 🟡 中 | 需实时更新球队状态 |
| **赛季末 (26-38轮)** | 充足数据 | 🟢 高 | 保级/争冠战意未建模 |
| **冬窗转会期** | 数据滞后 | 🟡 中 | 转会影响未建模 |

### 6.2 2026-2027 赛季关键缺口

#### 🔴 P0: 新赛季数据管线

当前系统无自动接入新赛季数据的能力：
- **无赛程导入**: 无法获取 2026-2027 赛季赛程
- **无自动赔率抓取**: 需手动执行 import 脚本
- **无结果自动录入**: 比赛结果需手动更新
- **无球队变更检测**: 升班马/降级队/转会无感知

#### 🔴 P0: 赛季冷启动方案

赛季前 5 轮面临严重冷启动问题：
- 升班马（如英冠→英超）无顶级联赛历史数据
- 新球员转会后球队实力评估不准确
- 赛季初阵容不稳定，赔率参考价值低

**当前无冷启动方案**。

#### 🟡 P1: 实时数据更新

赛季进行中需要实时更新：
- 球队近期状态（近 5 场滚动窗口）
- 赔率变化趋势（赛前 24 小时 → 赛前 1 小时）
- 突发伤病（赛前 6 小时）
- 天气/场地条件

#### 🟡 P1: 模型持续学习

当前模型仅支持**批量重训练**（weekly），不支持**在线学习**：
- 每场比赛后的结果无法立即反馈到模型
- 需要累积足够数据后才能重训练
- 赛季中期状态变化反映滞后

### 6.3 各预测类型能力评估

#### 胜平负预测 (T-005)

| 评估项 | 当前状态 | 2026-2027 需求 | 差距 |
|--------|----------|----------------|------|
| CV 准确率 | 51.24% | ≥55% | 需 +3.76pp |
| 赛季初准确率 | ~35% (估算) | ≥45% | 需引入新特征 |
| 升班马准确率 | ~20% (估算) | ≥35% | 需冷启动方案 |
| 保级战准确率 | ~48% (估算) | ≥55% | 需战意建模 |

**结论**: 赛季中期基本可用，赛季初和关键场次不可靠。

#### 比分预测 (T-006)

|--------|----------|----------------|------|

| 精确比分命中率 | ~25% | ≥30% | 需 +5pp |
