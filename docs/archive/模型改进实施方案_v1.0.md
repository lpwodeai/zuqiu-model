## 三、模块 A：赛后复盘闭环（P0）

> 对齐 [AI复盘闭环落地指南 阶段一+二](file:///F:/zuqiu/五大联赛专属模型/五大联赛专属模型/docs/AI复盘闭环落地指南_v1.0.md#三阶段落地路线图)。目标是先做「赛前→赛后」闭环，不碰赛中。

### A1. 赛后事实表 `post_match_review` + 实际结果回写

**新建表 DDL**（`data/odds.db`，对齐指南 §1.2，按现状精简）：

```sql
CREATE TABLE IF NOT EXISTS post_match_review (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    match_id        TEXT NOT NULL,
    league          TEXT,
    match_date      TEXT,
    home_team       TEXT,            -- 规范中文名（normalize_team_name）
    away_team       TEXT,
    actual_score    TEXT,            -- 如 "2:1"
    actual_half_score TEXT,
    actual_wdl      TEXT,            -- 主胜/平局/客胜
    actual_hcp      TEXT,            -- 上盘/走水/下盘
    actual_tg       INTEGER,
    pred_wdl        TEXT,
    pred_wdl_probs  TEXT,            -- JSON [ph,pd,pa]
    pred_score_top1 TEXT,
    pred_score_top5 TEXT,            -- JSON
    pred_hcp        TEXT,
    pred_tg         TEXT,
    wdl_correct     INTEGER,         -- 0/1
    score_top1_hit  INTEGER,
    score_top5_cover INTEGER,
    hcp_correct     INTEGER,
    tg_correct      INTEGER,
    single_rps      REAL,
    single_logloss  REAL,
    prob_rank       INTEGER,         -- 1/2/3
    attribution_json TEXT,           -- 归因引擎输出
    confidence_level INTEGER,        -- 1-5（3 级起才写因子库）
    data_quality_score REAL,         -- 0-1
    human_reviewed  INTEGER DEFAULT 0,
    human_notes     TEXT,
    created_at      TEXT DEFAULT (datetime('now','localtime')),
    reviewed_at     TEXT,
    UNIQUE(match_id)
);
```

**同时**：`model_predictions` 追加 4 行实际结果（`prediction_type='actual_wdl'/'actual_score'/'actual_tg'/'actual_hcp'`，`INSERT OR IGNORE` 幂等），使现有回测/报告链路无需改造即可读到赛果。理由：`model_predictions` 的 UNIQUE 约束是 `(match_id, model_name, prediction_type)`，追加新类型不破坏既有写入（对齐 EV_decision 七行先例）。

**落地文件**：
- 新建 `scripts/post_match_schema.py`（建表 + 幂等迁移函数 `ensure_post_match_schema(conn)`）
- 复用于 A2/A3/A4 所有写库路径

### A3. 归因引擎 `scripts/attribution_engine.py`

8 维度归因，每场输出带权重列表（权重和=100%），纯规则引擎实现（**不用 LLM 判断**，LLM 仅允许文字润色）：

| # | 归因维度 | 触发条件 | 数据来源 |
|:--:|---------|---------|---------|
| 1 | 数据缺失归因 | 关键特征缺失率 >20% | `sofascore_team_features` / 时序赔率 / 百家欧指 覆盖率 |
| 2 | 赔率异动归因 | 赛前 1h 竞彩赔率异动 >5% | 竞彩时序赔率（odds_timing / 竞彩末条） |
| 3 | 阵容异动归因 | 实际首发 vs `match_lineups` 差异 >3 人 | SofaScore 赛后首发 |
| 4 | 运气偏差归因 | 任一队 xG>1.5 且进球≤1，或 xG<0.5 且进球≥2 | Understat xG |
| 5 | 异常事件归因 | 有红牌/点球/乌龙 | SofaScore incidents |
| 6 | 战意归因 | 赛前战意评级 vs 投入度（跑动/抢断/犯规） | SofaScore 赛后统计 |
| 7 | 模型局限性归因 | 上述全不命中，且该类比赛历史偏差率高 | `post_match_review` 累计 |
| 8 | 校准偏移归因 | 单场预测概率 vs 模型该概率档历史命中率 | `model_performance` 分桶 |

**⚠️ 平局归因方向修正（重要）**：AI 指南原示例假设「模型对平局预测系统性偏低」——**与当前模型实际相反**。EV 回测已确认模型平局概率**系统性高于市场**（draw 方向 z=-2.86 显著负，7,291 笔平局价值投注 -4.47% 全线亏损）。故归因维度 8 的平局判断逻辑必须是：`平局概率高于该档市场隐含概率 且 实际非平局 → 归因「平局过度自信」`，而非「平局召回不足」。详见 [七、关键设计决策](#七关键设计决策与冲突修正)。

**输出 JSON 结构**（对齐指南 §2.1，`attribution_json` 字段）：

```json
{
  "attributions": [
    {"type": "阵容异动归因", "weight": 40, "description": "...", "evidence": {"lineup_diff": 4, "missing_players": ["前锋#9"]}}
  ],
  "primary_cause": "阵容异动归因",
  "confidence_level": 3
}
```

### A4. 自动复盘报告 `scripts/generate_post_match_report.py`

- 复用 `generate_unified_report.py` 的报告框架（章节结构 + markdown 模板 + 中文队名归一）
- 模板对齐指南 §2.2：① 比赛结果+关键事件时间线 → ② 预测 vs 实际对比（WDL/比分Top1/Top5/让球/大小球）→ ③ 预测质量评分（单场 RPS/LogLoss/概率排名/校准偏差，复用 `stratified_evaluation.py` 指标函数）→ ④ AI 归因（权重排序+证据）→ ⑤ 数据质量检查 → ⑥ 经验教训与改进建议 → ⑦ 因子库更新建议（带可信度）→ ⑧ 审核签字区

- 汇总页：`docs/post_match/{YYYYMMDD}/_summary.md`（当日全部分析命中/失败统计）

### A5. 可信度分级 + 人工审核流程

- 分级（对齐指南 §2.3）：1 纯模型 / 2 +部分外部数据 / 3 +完整外部数据 / 4 +人工确认 / 5 +同类≥3场重复验证；**≥4 级才写因子库**
- 审核通道：飞书推送（`lark-im`）复盘报告链接 → 打开「同意/不同意/部分同意」→ 同意自动升 4 级；不同意写备注触发重归因（人工备注写入 `human_corrections.json`，衔接模块 B4）
- 目标：每天审核 10 场 ≤15 分钟

### A6. 复盘链路数据质量门禁

## 七、关键设计决策与冲突修正

> 本方案相对 AI 复盘指南原文做 4 处修正，实施时必须遵循，避免把过时假设写进代码。

### 7.1 平局归因方向反转（最高优先）

- 指南示例假设：模型「平局预测系统性偏低（召回不足）」
- **实际（EV 回测证据）**：模型平局概率系统性**高于**市场（draw z=-2.86 显著负；77% 价值投注是平局且全线亏损）
- **决策**：归因引擎维度 8 的平局逻辑 = 检测「平局过度自信」；知识库 L3 平局条目 = 「重训时对平局样本降权/校准回市场水平」方向，**禁止**写「平局样本×1.2 加权」（该方向已被 P2-13 class_weights/Focal Loss A/B 证伪）

### 7.2 因子库定位：经验知识库，非权重库

- 模型是 GBDT，手动调权重不可行（指南已自我修正为 L1/L2/L3）
- 附加约束（来自本项目 A/B 门禁文化）：L2 特征层条目只用于**指导下一次实验**，不自动改参；P1-10/P2-10/P2-13 已验证否决的特征不得因知识库条目复活

### 7.3 赛后复盘与预测链路解耦

- `post_match_review` 是独立事实表（不挂在 `model_predictions` 上做字段扩展，避免破坏 UNIQUE 幂等与既有写库兼容）；实际结果以新 `prediction_type` 行方式追加写入 `model_predictions`，两表以 `match_id` 关联
- 复盘运行**不得**阻塞赛前预测 pipeline（`prediction-writer.js` 高并发写库，busy_timeout=5000 已固化）

### 7.4 数据质量优先于模型归因

- 归因排序固定：先查数据缺失（维度 1），缺失率 >20% 直接归因数据问题，不归因模型能力（对齐指南坑 3）
- `data_quality_score < 0.7` 不纳入性能统计

## 十、风险与回退

| 风险 | 等级 | 缓解/回退 |
|------|:--:|---------|
| C1 实盘验证无正 edge（300 注后 ROI≤0） | 中 | 按协议 300 注停止，关闭该段投注，结论写入知识库「证伪」条目；不影响模型主体 |
